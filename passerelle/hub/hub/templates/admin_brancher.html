Brancher un projet

Ce qu'il faut pour qu'un site, actuel ou futur, fonctionne derrière la passerelle : la clé à lui donner, des jetons pour les machines, et le code prêt à copier.

{{ ic("key", "s22 acc") }}La clé de la passerelle

Authentik l'ajoute à chaque visite d'une personne connectée (en-tête X-Passerelle-Cle). Le site s'en sert pour savoir que les en-têtes X-Authentik-* sont vrais. À mettre dans le .env de chaque site, jamais dans le code.

{{ ic("zap", "s22 acc") }}Un jeton pour une machine

Pour un outil qui appelle un site sans personne derrière : un autre site sur l'adresse locale, Home Assistant, un script, un connecteur MCP. Rien n'est enregistré ici : copie les deux lignes tout de suite.

Dans le .env du site appeléAjoute-le à la liste, séparé par une virgule.
Chez l'appelantEn-tête à envoyer à chaque appel. Pour un connecteur claude.ai : ajoute ?cle= et le jeton à l'adresse du /mcp.
Comment on entre dans un site
{{ ic("user") }}Une personne, dans un navigateur{{ ic("chev", "s18 chev") }}

Adresse : https://{{ ex }}. Authentik connecte la personne (une fois pour tous les sites), puis ajoute son e-mail, son nom et ses groupes dans X-Authentik-*, avec la clé. Le site n'a plus de page de connexion : il lit utilisateur().

Se déconnecter : lien vers /outpost.goauthentik.io/sign_out. Qui a le droit d'entrer : se règle dans Sites (Membres ou Admins).

{{ ic("wifi") }}Un outil sur l'adresse locale{{ ic("chev", "s18 chev") }}

L'adresse locale (http://192.168.1.60:3000) marche toujours, rien ne change dans le réseau. Ce qui change : le pare-feu Proxmox du site appelé ne laisse entrer que la passerelle et les machines que tu ajoutes.

Pour chaque site appelé en direct (BotPanel en premier, car tous tes sites lui envoient des notifications), ajoute une règle ACCEPT sur son port pour chaque appelant, ou un IPSet commun. Ces appels ne passent pas par Authentik : si l'appel lit ou modifie des données, exige un jeton.

{{ ic("cloud") }}Un service d'Internet (API, webhook){{ ic("chev", "s18 chev") }}

Ajoute le chemin dans Sites → le site → Chemins ouverts sans connexion (par exemple /api/github). Authentik laisse alors tout passer, sans rien vérifier : le site doit vérifier un jeton (Authorization: Bearer) ou une signature (signature_valide(), format BotPanel).

Une machine ne peut pas utiliser une adresse protégée : Authentik lui répondrait par la page de connexion.

{{ ic("plug") }}Un client MCP (Claude){{ ic("chev", "s18 chev") }}

Claude appelle depuis Internet : /mcp doit être un chemin public (c'est le réglage par défaut) et l'adresse du connecteur est https://{{ ex }}/mcp.

Le serveur MCP se protège lui-même : OAuth s'il le gère déjà, sinon un jeton. Les connecteurs claude.ai n'envoient pas d'en-tête : mets le jeton dans l'adresse (/mcp?cle=…). Claude Code, lui, envoie l'en-tête : claude mcp add --transport http nom https://{{ ex }}/mcp --header "Authorization: Bearer …".
